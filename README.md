# ecsly

**A high-performance Entity Component System for Dart.**

Data-oriented simulation speed for games and apps — on Flutter, web, Jaspr,
and CLI.

ecsly puts entities in cache-friendly archetypes, hot state in packed typed
columns with SIMD views, and structural changes behind deferred command queues
with explicit flush boundaries. Steady simulation frames run without
allocating. The core is pure Dart — no Flutter dependency, no native code —
and runs wherever Dart runs.

## Quick start

```sh
dart pub add ecsly
```

```dart
import 'package:ecsly/ecsly.dart';

class CounterComponent extends Component {
  CounterComponent(this.value);
  int value;
}

void main() {
  final world = World();
  world.components.registerObjectComponent<CounterComponent>();

  final entity = world.reserveEmptyEntity().entity;
  world.spawnBundle(entity, ComponentBundle.fromLists([CounterComponent(1)]));
  world.flush();

  world.createSchedule(ScheduleId.update).add((world) {
    for (final (_, counter) in world.queryMut<CounterComponent>()) {
      counter.value += 1;
    }
  });

  world.runSchedule(ScheduleId.update);
  world.flush();
}
```

Requires Dart SDK `>=3.12.0`. To run the examples from source:

```sh
git clone https://github.com/Arenukvern/ecsly && cd ecsly
dart pub get
cd core_packages/ecsly
dart run example/main.dart
```

## How ecsly stays fast

- **Archetype storage.** Entities with the same component set share packed
  `dart:typed_data` columns; queries iterate contiguous memory.
- **Two component tiers.** Object components for everyday modeling; typed
  extension components put hot numeric state in `FloatColumn`/`IntColumn`
  with SIMD (`Float32x4List`) views.
- **Deferred structural changes.** Spawns, despawns, and add/remove go through
  command queues and apply at explicit `flush()` boundaries — iteration stays
  stable and deterministic.
- **Cached queries.** Query results cache against a topology epoch that
  advances once per structural flush.

## Scope

ecsly owns simulation: entities, components, queries, systems, schedules,
events, commands, and resources. Rendering, input, physics, and audio belong
to the host — Flutter via `ecsly_flutter`, Jaspr, or your own engine layer.
The repo charter lives in [docs/NORTH_STAR.mdx](docs/NORTH_STAR.mdx);
positioning and claim rules in
[ADR 0005](docs/decisions/0005_high_performance_ecs_engine_positioning.md).
